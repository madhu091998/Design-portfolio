Simplifying contract management with AI

I worked on the end-to-end design of Contracts at Everstage, alongside the product manager and engineering team.

Contracts is the feature admins use to create and send sales compensation agreements to their salespeople.

The project involved moving away from DocuSign, bringing contract creation and signing into Everstage, and using AI to reduce the manual work involved in preparing contracts.

The problem

Companies send compensation agreements to their salespeople whenever they join, change roles, or start a new sales year. Each agreement contains information specific to that person, like their quota, commission plan, and compensation details.

Previously, we used DocuSign to create and send these contracts.

Admins had to build a template in DocuSign, download a CSV containing its fields, manually fill in the values for every salesperson, and upload it back into Everstage.

The bigger problem was that most of this information already existed in Everstage. Admins were spending time collecting and entering data that the product already had.

There was also no way to preview how each person's contract would look before sending it. If something was wrong, admins often found out only after sending the contract, which meant voiding it and sending another one.

On top of this, we were dependent on DocuSign for templates, permissions, and signing.

What we wanted to change

We wanted admins to create and send contracts without depending on DocuSign.

But instead of just rebuilding the same experience inside Everstage, we also wanted to reduce the manual work involved.

Since we already had much of the data needed to populate contracts, we explored how AI could help retrieve those values while still letting admins review and correct everything before sending.

What I designed

The new experience has two main parts: creating a contract template and sending contracts using that template.

1. Creating a template

Admins can upload a PDF, place placeholders, and configure recipients and signing order.

For each placeholder, they can describe what value is needed in plain language. Eva then finds it from existing Everstage data. They can also enter values manually, upload them, or set defaults.

2. Previewing AI-filled values

Admins can select a few salespeople to check how AI populates the placeholders.

They can review and correct the values, and preview the completed documents before confirming the template.

3. Reviewing before sending

Before sending, admins can review every recipient's placeholder values in a table.

They can spot missing values, edit them directly, or paste values from spreadsheets. They can also preview the final contracts.

4. Sending and tracking contracts

Admins can send contracts directly from Everstage, track signing progress, see who's yet to sign, and send reminders without relying on DocuSign.

Where AI fits

One of the main things I worked through was how AI should fit into an experience where the information needs to be accurate.

We didn't want AI to make every decision.

It helps find and populate the values, but admins still decide what information belongs in a contract, review the results, correct mistakes, and confirm when to send.

We also kept manual options because not every value can or should be fetched using AI.

What changed

With the new experience:

  • Contract creation and signing happen within Everstage, without DocuSign.
  • Admins can use existing product data instead of manually preparing every value in a spreadsheet.
  • AI can help populate placeholders based on plain-language instructions.
  • Admins can preview and correct values before sending.
  • Contracts and their signing status can be tracked within the product.

The new Contracts experience was introduced through a phased rollout.

What I took away

This project made me think more about what it means to design an AI experience.

Getting AI to populate a value is one part of the problem. The other is making sure people can understand what it has done, check whether it's right, and correct it when needed.

A lot of the design work went into making that part of the experience easier.
