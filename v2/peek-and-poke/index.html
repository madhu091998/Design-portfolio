Peek & poke

A Chrome extension for designers to make UI changes directly in the browser and turn them into instructions for AI coding tools.

Role
Product design, interaction design, visual design
Built with
Claude Code, Chrome extension, Figma plugin
Type
Self-initiated project

01The problem

It started with a lot of back and forth.

I've been using AI coding tools to prototype and make UI changes. While they've made building things much faster, explaining exactly what needs to change can still take a few tries.

A simple request like “increase the padding on this card” can lead to more questions. Which card? By how much? Should it change everywhere or just here?

And sometimes, the tool makes the change, just not quite where or how I intended.

02The idea

What if I could just point at what I wanted to change?

The browser already knows which element I'm looking at and what styles it's using.

So I started wondering if I could make changes directly on the page and pass those details to an AI coding tool, instead of explaining everything from scratch.

That became the starting point for Peek & poke.

03What I built

Element inspector

Making UI changes right where I see them.

With the Element inspector, I can select an element on a live page, change its styles, and see the result immediately.

Once I'm happy with the changes, the extension creates a prompt with the element details, updated values, and relevant design-system tokens that I can pass to Claude or Cursor.

  • Layout
  • Fill
  • Stroke
  • Typography
  • Appearance

Annotator

And while I was at it, I wanted to make feedback easier too.

Another thing I found inconvenient was leaving feedback on live builds. I'd usually have to take a screenshot, explain which element I was referring to, and move that feedback into Figma.

So I added an Annotator mode where I can click an element, leave a note or record one, and send everything to Figma with the annotations pinned to the right places.

Two experiments, one tool. Voice Annotator and Style Inspector started as separate experiments. I brought them together into Peek & poke after noticing that both begin with the same gesture: pointing at an element. The shared toolbar has two modes: Element inspector and Annotator.

04Design decisions

Scope

Changing one thing isn't always changing just one thing.

When I select a card, there might be five more cards using the same component.

Changing the selected card doesn't necessarily communicate whether I want to update just that instance or the shared component.

I introduced two options: “All” and “This one”, with “All” selected by default when matching elements are found.

This makes the scope visible in the browser and clear in the prompt, so the coding tool knows whether the change should affect a shared component or a single instance.

Hover states

A small interaction that took a few tries.

One issue I ran into was inspecting hover states. The moment I moved my cursor towards the inspector, the selected element would return to its default state.

I tried a few ways of keeping hover states active. Earlier versions supported locking multiple elements, but that introduced extra controls and made things more complicated than they needed to be.

I eventually simplified it to one pinned element at a time, with the current state clearly labelled in the inspector.

Design-system consistency

Making sure the changes still belong to the product.

I also wanted to avoid generating instructions that introduce random colours or typography styles into the product.

So I connected the inspector to our existing design-system tokens and text styles. When a value matches one of them, the generated prompt uses that token or component instead of introducing another hardcoded value.

That way, the changes are more consistent with how the product is already built.

05Building with AI

Designing it, and figuring out how to build it.

I built Peek & poke with Claude Code.

I worked on the problem, the interactions, the visual design, and the decisions along the way, while Claude helped turn those ideas into a working extension.

There was quite a bit of trial and error, especially around interactions that behaved differently on real web pages.

It's been an interesting way to work because I could try out ideas in the actual browser, see what wasn't working, and keep refining them.

06Outcome

A small tool that's still evolving.

Peek & poke started as something I wanted for my own workflow and eventually became a tool I could share with other designers.

There are still things I'd like to improve, especially around making it easier to work with existing design-system components.

For now, it's been a useful experiment in how designers can work a little more directly with the products they're building.

Ideas for later, not built yet

  • Recognise existing design-system components and swap to them
  • Generate token mappings from the design system automatically
  • Publish the extension to the Chrome Web Store
