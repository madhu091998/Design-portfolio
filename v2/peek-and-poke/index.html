Personal project · Design tooling · AI-assisted development

Peek & poke

A Chrome extension that lets designers edit UI right in the browser, then hand the change to an AI coding tool as a precise prompt.

Role
Product design, interaction design, visual design
Built with
Claude Code, Chrome extension, Figma plugin
Type
Self-initiated project

01The problem

Too much back and forth.

I use AI coding tools to prototype and tweak UI. They're fast, but describing a change in words still takes a few rounds.

“Increase the padding on this card.” Which card? By how much? Just this one, or all of them? And sometimes the change lands, just not where I meant.

02The idea

What if I could just point at it?

The browser already knows which element I'm looking at and which styles it uses. So instead of describing a change, I could make it on the page and pass those details straight to the AI tool.

03What I built

Element inspector

Edit on the page, copy a prompt.

Select any element on a live page, adjust its styles and see the result instantly. When it looks right, copy a prompt with the element, the new values and matching design-system tokens, ready for Claude or Cursor.

Annotator

Feedback, pinned to the element.

Feedback on a live build used to mean screenshots and explaining which element I meant. In Annotator mode, I click an element, type or say a note, and send it all to Figma with each note pinned in place.

Two tools, one gesture. Annotator and the inspector started as separate experiments. Both begin with pointing at an element, so I merged them into one toolbar with two modes.

04Design decisions

Scope

One card is rarely just one card.

A selected card often shares a component with five others, and editing it doesn't say which I mean. So the inspector asks: All or This one. All is the default when there are matches, the matches get dashed outlines, and the choice goes into the prompt.

Hover states

Hover lock took three tries.

Moving the cursor to the inspector dropped the element's hover state, so I couldn't read it. Early versions let me lock several elements, which needed extra UI just to manage. The final one pins one element at a time and labels the state in the inspector.

Design-system consistency

Stay on the design system.

I didn't want prompts that sneak random hex codes or type styles into the product. The inspector knows our tokens and text styles, so when a value matches one, the prompt uses the token instead of a hardcoded value.

05Building with AI

Designed by me, built with Claude Code.

I owned the problem, the interactions, the visual design and the decisions. Claude Code wrote the implementation.

Most of the work was trial and error on real pages: try an idea in the browser, see what breaks, refine.

06Outcome

Still evolving.

It started as a tool for my own workflow and is now something I share with other designers. Next, I'd like it to work better with existing design-system components.
